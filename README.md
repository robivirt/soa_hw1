# Архитектура

За каждый вид взаимодействия отвечает отдельный микросервис. Всего используется две базы для хранения данных: одна хранит пользователей и их заказы, вторая отвечает за товары в каталоге. Все взаимодействия синхронные для упрощения реализации, но взамен меньшая производительность. Добавление новой функциональности будет менять 1 сервис и не повлияет на другие.

# Запуск

```sh
$ docker build -t notifier-service .
$ docker run -p 8000:8000 notifier-service
$ curl -v localhost:8000/health
```
